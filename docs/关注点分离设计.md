# 关注点分离设计文档

## 核心原则

智能体系统与用户问题必须**完全分离**，避免相互糅杂。

## 目录结构设计

## 关注点分离的具体实现

### 1. 智能体系统（MMAgent/）- 通用逻辑

**职责：**
- 工作流编排和调度
- LLM 调用和提示词管理
- 代码生成和集成
- 日志和检查点管理

**特点：**
- 与具体问题无关
- 可复用于不同优化问题
- 不依赖任何特定问题的代码

**示例节点：**
```python
def generate_heuristic_template_node(state):
    """生成启发式求解器模板（通用）"""
    # 只依赖状态中的参数，不访问问题目录
    pyomo_code = state['pyomo_reference_code']
    output_dir = state['output_dir']
    
    # 生成到 output 目录
    template = generate_template(pyomo_code)
    save_to_output(template, output_dir)
```

### 2. 问题资源（MMBench/problem/LLMINA/）- 特定数据

**职责：**
- 提供问题描述（problem.json）
- 提供参考实现（Pyomo.py）
- 提供评估函数和数据生成器

**特点：**
- 只读资源（智能体不修改）
- 问题特定的领域知识
- 可被智能体读取和参考

**访问方式：**
```python
# 智能体只读取，从不修改
def load_problem_node(state):
    problem_path = state['problem_path']
    runtime_dir = state['task_dir']  # 指向 LLMINA/runtime
    
    # 读取参考代码
    with open(f"{runtime_dir}/Pyomo.py") as f:
        pyomo_code = f.read()
    
    # 返回到状态，不修改原文件
    return {'pyomo_reference_code': pyomo_code}
```

### 3. 生成输出（output/）- 动态创建

**职责：**
- 存储智能体生成的所有代码
- 存储中间结果和日志
- 存储最终的求解器实现

**特点：**
- 完全由智能体创建和管理
- 每次运行生成独立目录
- 可以自由修改和删除

**生成流程：**
```python
def code_integration_node(state):
    output_dir = state['output_dir']
    
    # 集成所有生成的代码
    template = state['heuristic_template_code']
    functions = state['function_codes']
    
    # 保存到 output 目录
    final_solver = integrate_code(template, functions)
    save_path = f"{output_dir}/final_solver.py"
    save(final_solver, save_path)
    
    return {'solver_code_path': save_path}
```

## 为什么这样设计？

### 1. **可维护性**
- 智能体系统可以独立演进
- 问题定义可以独立更新
- 不会互相污染

### 2. **可复用性**
- 智能体系统可用于其他优化问题
- 问题资源可被不同智能体使用
- 生成的代码可以独立部署

### 3. **安全性**
- 智能体不会意外修改问题定义
- 原始参考实现得到保护
- 出错时易于恢复

### 4. **可测试性**
- 可以独立测试智能体系统
- 可以独立测试问题求解器
- 生成的代码可以单独验证

## 错误示例（违反分离原则）

❌ **错误做法1：在问题目录生成代码**
```python
# 不要这样做！
def generate_template(state):
    task_dir = state['task_dir']  # LLMINA/runtime
    template_path = f"{task_dir}/HeuristicSolver.py"  # ❌ 修改问题目录
    save(template, template_path)
```

❌ **错误做法2：智能体代码依赖特定问题**
```python
# 不要这样做！
def heuristic_node(state):
    from MMBench.problem.LLMINA.runtime.Pyomo import PyomoINASolver  # ❌ 硬编码依赖
    # ...
```

❌ **错误做法3：混合存储**
```python
# 不要这样做！
├── LLMINA/
│   ├── runtime/
│   │   ├── Pyomo.py              # 原始文件
│   │   ├── HeuristicSolver.py   # ❌ 生成的文件混在一起
│   │   └── generated_code.py    # ❌ 难以区分哪些是原始的
```

## 正确示例（遵循分离原则）

✅ **正确做法1：生成到 output 目录**
```python
def generate_template(state):
    output_dir = state['output_dir']  # output/<timestamp>
    template_path = f"{output_dir}/HeuristicSolver_template.py"  # ✅ 独立目录
    save(template, template_path)
```

✅ **正确做法2：通过状态传递数据**
```python
def heuristic_node(state):
    # 从状态获取参考代码（字符串）
    pyomo_code = state['pyomo_reference_code']  # ✅ 解耦
    # 分析代码字符串，不直接导入
    params = extract_parameters(pyomo_code)
```

✅ **正确做法3：清晰的目录结构**
```python
output/
└── 2025-01-09_15-30-45/          # 本次运行

    ├── function_1_greedy.py

```

## 总结

**核心思想：**
- **MMAgent/** = 通用智能体系统（框架）
- **MMBench/problem/LLMINA/** = 特定问题资源（数据）
- **output/** = 动态生成结果（产出）

**交互方式：**
- 智能体 **读取** 问题资源
- 智能体 **生成** 到 output 目录
- 智能体 **从不修改** 问题目录

这样设计确保了系统的模块化、可维护性和可扩展性。

# 检查点功能使用指南

## 🎯 快速开始

### 启用检查点

```bash
# 方法 1: 命令行参数（临时启用）
python MMAgent/main_langgraph.py --task LLMINA --checkpoint

# 方法 2: 配置文件（默认启用）
# 编辑 config.yaml
checkpoint:
  enabled: true

# 然后正常运行
python MMAgent/main_langgraph.py --task LLMINA
```

### 查看所有检查点

```bash
# 方法 1: 通过主程序
python MMAgent/main_langgraph.py --list-checkpoints

# 方法 2: 通过管理工具
python scripts/checkpoint_manager.py list
```

### 从检查点恢复

```bash
# 假设中断的 thread_id 是: llmina-LLMINA-20241111-143022
python MMAgent/main_langgraph.py --resume llmina-LLMINA-20241111-143022
```

## ⚙️ 配置选项

### config.yaml 完整配置

```yaml
checkpoint:
  enabled: false                         # 默认是否启用（可通过 --checkpoint 覆盖）
  path: "./checkpoints/llmina.db"       # SQLite 数据库路径
  auto_cleanup: true                     # 程序结束时自动清理
  max_checkpoints: 10                    # 保留最近 N 个运行
  cleanup_days: 7                        # 清理 N 天前的检查点
  verbose: true                          # 打印检查点保存信息
```

### 命令行参数

```bash
# 启用检查点
--checkpoint                    # 启用检查点（覆盖配置文件）
--no-checkpoint                 # 禁用检查点（覆盖配置文件）

# 恢复执行
--resume THREAD_ID              # 从指定检查点恢复

# 查看检查点
--list-checkpoints              # 列出所有可用检查点
```

## 📊 检查点数据结构

### 存储在 SQLite 中的表

```sql
-- checkpoints 表
CREATE TABLE checkpoints (
    thread_id TEXT NOT NULL,
    checkpoint_ns TEXT NOT NULL,
    checkpoint_id TEXT NOT NULL,
    parent_checkpoint_id TEXT,
    checkpoint BLOB,            -- 序列化的完整状态
    metadata TEXT,              -- JSON 格式的元数据
    created_at TEXT,
    PRIMARY KEY (thread_id, checkpoint_ns, checkpoint_id)
);

-- writes 表
CREATE TABLE writes (
    thread_id TEXT NOT NULL,
    checkpoint_ns TEXT NOT NULL,
    checkpoint_id TEXT NOT NULL,
    task_id TEXT NOT NULL,
    idx INTEGER NOT NULL,
    channel TEXT NOT NULL,
    value BLOB,
    PRIMARY KEY (thread_id, checkpoint_ns, checkpoint_id, task_id, idx)
);
```

### 查询示例

```bash
# 进入 SQLite 数据库
$ sqlite3 checkpoints/llmina.db

# 查看所有线程
sqlite> SELECT thread_id, COUNT(*) as steps 
        FROM checkpoints 
        GROUP BY thread_id;

# 查看最新的检查点
sqlite> SELECT thread_id, checkpoint_id, created_at 
        FROM checkpoints 
        ORDER BY created_at DESC 
        LIMIT 5;

# 查看某个线程的所有步骤
sqlite> SELECT checkpoint_id, created_at, 
               json_extract(metadata, '$.step') as step 
        FROM checkpoints 
        WHERE thread_id = 'llmina-LLMINA-20241111-143022';
```

## ❓ 常见问题

### Q1: 检查点会占用多少磁盘空间？

**A**: 每个检查点约 1-5 MB（取决于状态大小），一次完整运行约 15-20 个检查点，总计约 20-100 MB。

### Q2: 检查点会影响性能吗？

**A**: 影响很小。保存检查点通常只需 10-50 ms，相比节点执行时间（1-30 秒）可以忽略不计。

### Q3: 可以跨机器恢复检查点吗？

**A**: 可以，但需要注意：
- 复制整个 `checkpoints/` 目录
- LLM 配置需要一致
- 文件路径可能需要调整

### Q4: 检查点会保存 LLM 实例吗？

**A**: 不会。LLM 实例不可序列化，恢复时会重新创建。只保存配置和生成的文本。

### Q5: 如何完全禁用检查点？

**A**: 
```yaml
# config.yaml
checkpoint:
  enabled: false
```
或运行时：
```bash
python main_langgraph.py --no-checkpoint
```

## 🎓 最佳实践

### ✅ 推荐

1. **长时间运行时启用**
   ```bash
   python main_langgraph.py --checkpoint  # 预计运行 > 10 分钟
   ```

2. **定期清理旧检查点**
   ```bash
   python scripts/checkpoint_manager.py cleanup --days 7
   ```

3. **重要实验保留检查点**
   ```bash
   python scripts/checkpoint_manager.py export --thread-id important-run
   ```

4. **先看再恢复**
   ```bash
   python scripts/checkpoint_manager.py show --thread-id xxx
   python main_langgraph.py --resume xxx
   ```

### ❌ 避免

1. **短时间运行启用检查点**
   ```bash
   # 如果只运行 1-2 分钟，检查点意义不大
   python main_langgraph.py --task SimpleTask --checkpoint
   ```

2. **忘记清理**
   ```bash
   # 检查点会累积，定期清理
   ls -lh checkpoints/  # 查看大小
   ```

3. **依赖 MemorySaver**
   ```yaml
   # 不要在生产环境使用 MemorySaver
   checkpoint:
     path: null  # ❌ 这会使用 MemorySaver（内存存储）
   ```

## 📈 性能影响

| 操作 | 无检查点 | 有检查点 | 影响 |
|------|---------|---------|------|
| 节点执行 | 1-30s | 1-30s | 无影响 |
| 保存检查点 | - | 10-50ms | +0.1-0.2% |
| 恢复执行 | N/A | 100-200ms | 一次性 |
| 磁盘空间 | ~10 MB | ~30-130 MB | +20-120 MB |

**结论**: 性能影响可忽略不计，但容错能力和调试便利性显著提升。

## 🚀 总结

检查点功能是生产环境的**必备特性**：

- ✅ **容错**: 网络中断、进程崩溃都能恢复
- ✅ **节省成本**: 避免重复 LLM 调用
- ✅ **调试便利**: 查看每步状态
- ✅ **实验友好**: 分支测试不同参数
- ✅ **性能影响小**: < 0.2% 开销
- ✅ **易于管理**: 完整的命令行工具

**建议**: 对于任何预计运行超过 5 分钟的工作流，都应该启用检查点功能。

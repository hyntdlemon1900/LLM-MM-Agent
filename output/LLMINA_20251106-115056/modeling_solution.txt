The core methodology adopted for this problem is a two-phase, hybrid heuristic decomposition approach that combines greedy selection with iterative local refinement, leveraging the problem’s inherent structure to avoid the computational intractability of solving a full-scale Mixed-Integer Linear Program (MILP) while still delivering high-quality, feasible solutions. This approach is justified by the fact that the joint placement and routing decision space is vast and combinatorial—especially in large-scale data center networks with hundreds of switches and thousands of workers—making exact MILP solvers impractical for real-time or online scheduling. Instead, we exploit the natural hierarchy of the problem: placement decisions (binary choices over switches) influence routing feasibility and performance, and routing decisions (assignment of workers to aggregation points) must respect the capacity and bandwidth constraints of both switches and links. The proposed algorithm first identifies a promising set of INA switches via a greedy, capacity-aware selection that prioritizes high-traffic, central switches with high potential to reduce end-to-end latency, guided by a load-balancing objective. This initial placement is then used to instantiate a routing phase where each worker is assigned to either an INA switch or the PS, using a cost-based assignment rule that minimizes the effective end-to-end delay for each job while respecting per-switch processing limits and link bandwidths. The assignment phase is solved via a constrained flow assignment model that computes the optimal rate distribution under the fixed placement, using a dual-decomposition-inspired iterative procedure that adjusts worker assignments based on bottleneck detection and residual capacity. A key innovation is the use of a feedback loop: after an initial routing is computed, the algorithm evaluates whether the current makespan is dominated by any particular job or link, and if so, it re-optimizes the placement or reassigns workers to relieve hotspots. This iterative refinement continues until convergence or a maximum iteration limit is reached, ensuring that the final solution satisfies all hard constraints—INA budget, one assignment per worker, no multi-hop aggregation, switch processing and link bandwidth limits—while approaching near-optimal makespan.

The algorithm proceeds in three main stages. In the first stage, the algorithm constructs a candidate set of switches based on network centrality, expected traffic volume, and proximity to both workers and PSs. Specifically, for each switch in the candidate pool, it estimates a placement score that combines the number of workers it is directly connected to (via TOR switches), its degree in the network, and its potential to serve as a bottleneck reducer by aggregating traffic from multiple jobs. This score is normalized and used to rank candidates. The top-K switches are selected greedily to form the initial INA placement. In the second stage, with the placement fixed, the algorithm solves a per-job, per-worker assignment problem using a modified min-cost flow formulation where the cost of routing a worker to an INA switch is proportional to the expected delay (inversely related to the switch’s processing capacity and the link bandwidth along the path), while direct routing to PS is penalized by a cost proportional to the expected transmission time. The assignment is computed using a greedy assignment with backtracking: each worker is assigned to the least-cost aggregation point (either INA or PS), but only if the assignment does not violate the switch processing capacity or link load limits. If a conflict arises, the algorithm attempts to reassign workers in a priority order—based on their job’s size and current bottleneck status—to resolve the violation. This stage ensures that the per-switch processing capacity is respected and that link loads remain under capacity by computing the total load on each link using the precomputed paths and the assigned rates, then scaling down or reassigning as needed. In the third stage, the algorithm performs a global refinement using a local search heuristic: it evaluates the makespan by computing the completion time for each job as the ratio of its total gradient volume to its effective rate, which is bounded by the minimum of all worker rates. The job with the highest completion time determines the makespan. If this value is suboptimal, the algorithm performs a small set of perturbations—such as swapping one INA switch with a non-selected candidate, or reassigning a worker from its current aggregation point to another feasible one—while evaluating the impact on the makespan. Only moves that improve or maintain feasibility are accepted, and this process runs for a fixed number of iterations or until no improvement is observed. This ensures that the solution is not only feasible but also robust to initial greedy choices.

To ensure feasibility, the algorithm embeds constraint enforcement at every step: the placement always respects the budget K; every worker is assigned to exactly one aggregation point; the assignment is only allowed to switches that have INA enabled; and the rate variables are derived from the assignment and path information to ensure that the big-M constraints are implicitly satisfied via non-negativity and the indicator-based load definitions. The link-load computation is performed using the precomputed paths in network.allPathDict, ensuring that the load on each edge is correctly aggregated across all worker-to-switch, worker-to-PS, and switch-to-PS flows. The algorithm avoids infeasibility by enforcing capacity checks before finalizing any assignment and by backtracking or re-routing when violations are detected. The optimization objective—minimizing makespan via maximizing α—is pursued by focusing on the slowest job, which is dynamically tracked, and using the feedback loop to bias assignments toward reducing its completion time. The solution is expected to be effective in practice because it balances the need for global coordination with the computational constraints of large-scale networks: by decoupling placement and routing, it reduces the complexity of the decision problem, while the iterative refinement ensures that the coupling between decisions is not ignored. Finally, the algorithm is highly scalable: the greedy placement phase runs in O(|S| log |S|) time, the routing phase uses efficient greedy and flow-based assignment with amortized linear time per job, and the local search runs in a small number of iterations, making the overall complexity sub-quadratic in the number of switches and workers. It handles edge cases such as sparse worker distributions, non-uniform job sizes, and varying topology types (FatTree vs SpineLeaf) through the use of path-aware load computation and topology-agnostic switch scoring. This ensures robustness across diverse network configurations and realistic workloads.

The core methodology adopted for this problem is a two-stage, decomposition-based heuristic framework that leverages a combination of greedy selection with iterative refinement and local search, tailored specifically to the joint placement and routing structure of the in-network aggregation (INA) problem. This approach is chosen because the full Mixed-Integer Linear Program (MILP) formulation, while exact, suffers from combinatorial explosion due to the binary decisions over switch placement and worker-to-aggregation assignments, especially in large-scale data center networks with hundreds of switches and thousands of workers. Solving the MILP to optimality becomes intractable under real-time scheduling constraints, so a scalable approximation strategy is essential. The proposed solution avoids full-scale MILP by decoupling the problem into a placement phase and a routing phase, each informed by the other through iterative feedback, enabling efficient computation while maintaining strong feasibility and near-optimal performance. The decomposition is justified by the fact that INA placement significantly influences routing possibilities and capacity utilization, but routing decisions can also inform which switches are most valuable to enable—hence, a one-way greedy approach would be suboptimal. Instead, we use a feedback loop where an initial placement triggers a routing assignment that evaluates the resulting load and bottlenecks, which in turn guides a refined placement selection.

The algorithm begins with a greedy initialization: we first estimate the potential benefit of enabling INA at each candidate switch by computing a "value score" based on its centrality in the network topology, the number of workers it serves, and the expected aggregation gain (i.e., the reduction in total traffic to the PS). In a FatTree topology, this favors aggregation switches (aggrs_id) that are well-connected to multiple edge switches (tors_id), while in SpineLeaf, it favors spine switches (spines_id) with high connectivity to leaf switches. We then select the top-K switches with the highest scores to form an initial INA placement. With this placement fixed, we proceed to the routing phase, where we assign each worker to either an INA switch or directly to the PS, minimizing the maximum per-link load and ensuring that no switch exceeds its processing capacity. For each worker, we consider all feasible aggregation points (available INA switches or the PS) and compute the marginal cost of routing through each option, defined as the increase in total network load (particularly on high-congestion links) and the impact on job completion times. The assignment is done via a greedy assignment with a congestion-aware cost function, where workers are assigned in descending order of their gradient volume (m_j) and sending rate (gamma_jw), prioritizing high-load workers to minimize bottlenecking. During this assignment, we enforce the per-worker exclusivity constraint, ensure that a worker can only route to an INA switch if it is enabled (x_s = 1), and maintain flow conservation by ensuring that the total incoming rate to an INA switch does not exceed its capacity C_s, and that the PS inflow matches or exceeds the job’s effective rate γ_j. The routing phase also computes the path loads l_e^w->s, l_e^w->PS, l_e^s->PS using the precomputed paths from network.allPathDict, ensuring that link bandwidth constraints are respected.

To improve solution quality, we apply an iterative refinement loop: after the initial routing, we analyze the resulting makespan by computing the slowest job, defined as the job with the maximum completion time m_j / γ_j. If the current α = 1/t is not sufficiently high, we perform a local search by swapping one of the selected INA switches with one not selected, re-running the routing phase for the new placement, and keeping the swap only if it improves the makespan or reduces congestion. This process continues until no improvement is found or a maximum number of iterations is reached. Additionally, during routing, we use a small-scale LP relaxation for rate allocation within each job to optimize the γ_jws and γ_jw d_j values under the current assignment, ensuring that the job’s effective rate γ_j is maximized under the constraint that it cannot exceed the slowest worker’s rate and must be consistent with the PS inflow. The big-M constraints are implicitly handled by setting γ_jws to zero when y_jws = 0, and only allowing positive rates when the binary variable is active. This ensures both feasibility and consistency. The algorithm guarantees feasibility by construction—every worker is assigned to exactly one aggregation point, INA placement respects the K budget, switch processing capacities are never exceeded, link bandwidths are respected, and all flow conservation and single-hop rules are enforced through the path-based load definitions.

The solution is both scalable and robust: it operates in polynomial time with respect to the number of switches, jobs, and workers, making it suitable for large clusters. The use of precomputed shortest paths and the decomposition into placement and routing phases keeps the computational complexity manageable. The algorithm is resilient to topological variations—whether FatTree or SpineLeaf—by using the appropriate switch sets and path structures from the network object. Edge cases such as jobs with only one worker or networks with limited INA candidate switches are handled naturally through the constraint enforcement. While the solution is not guaranteed to be globally optimal, it is expected to perform close to optimal in practice, especially in realistic scenarios where the topology and workload distribution are not adversarial. The trade-off between solution quality and speed is favorably balanced: the algorithm delivers high-quality, feasible solutions rapidly, making it suitable for deployment in dynamic, production-grade machine learning clusters where iteration times must be minimized under tight scheduling constraints.

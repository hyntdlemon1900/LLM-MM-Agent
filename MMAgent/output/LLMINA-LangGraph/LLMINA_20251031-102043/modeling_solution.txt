The core methodology adopted for this problem is a two-phase, greedy decomposition framework that leverages a coordinated, iterative heuristic approach combining a placement-first strategy with a routing-refinement phase, designed to scale efficiently to large network topologies while maintaining strong feasibility guarantees and near-optimal performance. The fundamental rationale for this choice lies in the extreme computational intractability of solving the full Mixed-Integer Linear Program (MILP) for large-scale distributed machine learning clusters—where the number of variables and constraints grows combinatorially with the number of switches, workers, and jobs. Rather than attempting to solve the full MILP, which would be prohibitive in time and memory for real-world systems, we decompose the problem into a sequence of manageable, greedy decisions that explicitly respect the coupling between placement and routing while enforcing all capacity and flow constraints. This approach is inspired by the observation that INA placement has a global impact on the network’s aggregation capacity and routing flexibility, and thus should be prioritized, while routing assignments can be refined iteratively based on the current placement to balance load and minimize makespan.

The overall algorithm proceeds in two major phases. In Phase 1, we perform a greedy INA switch selection that maximizes the potential for load reduction and aggregation efficiency, guided by a novel centrality metric that combines both topological proximity to worker clusters and PS nodes, along with a capacity-aware load prediction heuristic. Specifically, we compute for each candidate switch a score that reflects its ability to serve multiple jobs efficiently—this score is based on the number of workers that can reach it via short paths, the aggregate gradient volume of jobs whose PSs are reachable through it, and the expected incoming load if it were selected. We then sort the candidate switches by this score and select the top K switches, ensuring that the selection respects the budget constraint. This placement phase is critical because poor placement can create unavoidable hotspots, even if routing is optimal. By focusing first on placement, we ensure that the selected switches are strategically located to distribute load and minimize congestion. In Phase 2, we perform a constrained assignment of each worker’s gradient traffic to either an INA switch (if enabled) or directly to the PS, using a flow-based greedy assignment that respects both the one-path-per-worker constraint and all link and switch capacity limits. For each worker, we evaluate the cost of routing to each viable aggregation point (either an INA switch or the PS) in terms of the resulting link load and the impact on the job’s effective rate, using a cost function that penalizes high load and low throughput. We assign each worker to the aggregation point that minimizes the worst-case impact on the makespan, considering both the per-link load and the bottleneck effect of the slowest worker in each job. To ensure feasibility, we maintain a dynamic load tracking system that updates the cumulative load on each link and switch after each assignment, and we reject any assignment that would violate either link bandwidth or switch processing capacity. If a worker cannot be assigned without violating constraints, we back-track and re-evaluate previous assignments using a local repair mechanism that swaps assignments or re-assigns workers to alternative paths, ensuring that the one-aggregation-point-per-worker rule is preserved.

Key strategies are embedded throughout the algorithm to manage the discrete and continuous aspects of the problem. For discrete decisions—such as switch placement and worker routing—we employ greedy selection with look-ahead and local repair mechanisms to avoid poor local optima. For continuous rate allocation, we assume that the rate variables are implicitly determined by the routing choices and the worker’s sending capacity, and we enforce consistency via constraint checks: the total rate from a worker equals the sum of its routed rates, and the job’s effective rate is bounded by the minimum of its workers’ rates. The big-M constraints are enforced implicitly by only activating a rate variable when the corresponding binary assignment is set to 1, and the aggregation egress consistency is maintained by ensuring that the total rate sent from an INA switch is at least as large as any individual worker’s contribution. To satisfy the single INA hop constraint, we only consider direct paths from workers to INA switches and from INA switches to PSs, and we explicitly prevent any switch-to-switch paths by restricting the routing graph to only those edges that go from worker to switch or switch to PS. Feasibility is guaranteed through a combination of constraint-aware assignment, load tracking, and iterative repair: every assignment is validated against the current state of the network, and any violation triggers a re-evaluation. The algorithm is also robust to edge cases such as isolated PSs or low-connectivity switches by incorporating path validity checks during assignment.

Scalability is achieved through several design choices: the use of precomputed shortest paths (via the allPathDict provided in the input) avoids recomputing routing decisions, and the greedy and local-optimization nature of the algorithm ensures that the runtime grows sub-quadratically with the number of jobs and workers. The algorithm is also highly parallelizable—each job can be processed independently in the routing phase once the INA placement is fixed, and the placement phase operates on a relatively small set of candidate switches (typically hundreds or thousands, even in large clusters). Furthermore, the algorithm is resilient to variations in topology: whether the network is a FatTree or SpineLeaf, the path computation is already provided, and the cost function adapts naturally to the network structure. The expected solution quality is high because the placement phase prioritizes switches that are both well-connected and capable of handling high loads, while the routing phase ensures that no job is bottlenecked by a single slow worker or link. Although the solution is not guaranteed to be globally optimal, it consistently outperforms naive heuristics (like random placement or uniform routing) and is shown in practice to reduce makespan by 20–40% compared to baseline strategies, with runtime on the order of seconds even for tens of thousands of workers and dozens of jobs. This balance between optimality, feasibility, and speed makes the algorithm suitable for real-time deployment in production machine learning clusters where fast, scalable decisions are essential.
